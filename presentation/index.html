The Problem

The Musicians' Practice Blindspot

Traditional music practice lacks objective, quantitative performance metrics.

✕ The Practice Dilemma

  • Intonation Drift: The human ear adapts to pitch errors, making it difficult for students to detect ±15 cents deviations while playing.
  • Rhythmic Inconsistency: Subtle micro-tempo rushes or drags (20–50ms) degrade musicality but go unnoticed without objective measurement.
  • Subjective Memory: Musicians cannot reliably measure if their 10th practice run was technically better than their 1st run.
  • Device Compute Bottleneck: Running heavy TensorFlow or PyTorch models on mobile phones drains battery and throttles CPU chips.

✓ The Practice Tracker Solution

  • Sub-Cent Pitch Intonation: Precise frequency analysis calculating exact deviation against equal temperament ($A_4 = 440\text{Hz}$).
  • Beat-by-Beat Alignment: Visual millisecond offset timeline showing whether notes landed early, late, or dead-on.
  • Smart Piece Tracking: Melodic fingerprinting automatically tracks historical mastery across practice sessions.
  • Cloud-Offloaded Inference: Heavy neural processing executes on Google Cloud Run in seconds with zero phone overheating.
Speaker Notes: Emphasize that music students spend hours practicing mistakes because they lack immediate, quantitative feedback. Practice Tracker solves this objectively.

Deep Learning & DSP

Dual AI Inference Engines

Tailored neural architectures for polyphonic vs. monophonic instruments.

🎹 Polyphonic Engine: Spotify Basic Pitch

Instruments: Piano, Guitar, Polyphonic Keyboard.

  • Neural Architecture: Convolutional + recurrent deep neural network that evaluates overlapping frequencies.
  • Key Capability: Separates polyphonic chords (e.g., C-E-G played simultaneously) where classic algorithms fail.
  • Calculated Metrics: Discrete MIDI note events, start/stop seconds, confidence probability, and frequency intonation.
[{"midi": 60, "label": "C4", "onset_s": 0.42, "offset_s": 0.98, "cents_error": -3.2}]

🎻 Monophonic Engine: CREPE

Instruments: Voice, Violin, Viola, Flute, Cello.

  • Neural Architecture: Deep convolutional network operating directly on raw time-domain waveforms.
  • Key Capability: Tracks continuous fundamental frequency ($f_0$) every 10ms with sub-cent precision.
  • Calculated Metrics: Microtonal pitch contour, vocal scoops, vibrato width, and intonation drift.
cents_error = 1200 * log2(f0 / f_target)
Speaker Notes: Explain why a single ML model is not enough: monophonic instruments require continuous pitch contouring, whereas polyphonic instruments require note separation.
Rhythm Analytics

Beat Synchronization & Timing Engine

Quantifying musical groove, tempo drift, and metronome alignment.

1. Spectral Flux Onset

Analyzes spectral energy differentials across successive audio frames to pin down the exact millisecond a note is struck or vocalized.

onset_env = librosa.onset.onset_strength(y=y, sr=sr)

2. Metronome Grid Lock

Generates an exact theoretical beat timeline based on target BPM (e.g., 120 BPM = 500ms beat intervals) or auto-detects tempo periodicity.

beat_times = [i * (60.0 / bpm) for i in range(N)]

3. Millisecond Deviation

Maps each note onset to the nearest beat marker:

  • On-Beat: Error within $\pm 35\text{ms}$
  • Rushed / Early: Negative ms offset
  • Dragged / Late: Positive ms offset
  • Tempo Steadiness: Onset std-dev
Speaker Notes: This timing engine powers the timing review screen where musicians can see whether their rhythm is rushing during difficult technical passages.

Data Pipeline

End-to-End Request Lifecycle

From microphone capture to neural analysis and visual rendering.

Step-by-Step Flow

  1. Musician Captures Audio: Mobile app records 44.1kHz audio and prompts for instrument and tempo.
  2. Multipart Upload: Mobile sends POST /sessions/analyze-direct with Bearer token.
  3. Session Creation: core-api registers a session in Cloud SQL marked processing.
  4. ML Routing & Streaming: core-api streams raw audio directly to worker-poly or worker-mono.
  5. Neural Transcription: Worker computes note events, intonation cents, and onset alignment.
  6. Database Commit: core-api commits results to Cloud SQL and marks session completed.
  7. Visual Feedback: Mobile renders dynamic Piano Roll and Timing Timeline.

Cloud Benefits

Strategic Engineering Benefits of GCP

Why building on Google Cloud was the optimal engineering decision.

⚡ Compute Offloading & Battery Preservation

Running Spotify Basic Pitch or CREPE on a phone causes significant device throttling, battery drain, and thermal heating. Offloading inference to Cloud Run containers executes models on multi-core cloud CPUs in under 3 seconds.

💰 Cost Efficiency (Scale to Zero)

Traditional servers (like VMs or EC2 instances) charge 24/7 even when idle. Cloud Run scales to zero instances when no musicians are practicing, reducing compute costs to pennies during off-peak hours.

🛡️ Enterprise Data Security

Cloud SQL protects student data with encryption at rest and in transit. By connecting via Cloud SQL Auth Proxy Unix sockets, database ports are completely blocked from the public internet.

🌐 Sub-5ms Internal Latency

Colocating all resources in the same cloud region (asia-south1) ensures that data transfer between API gateway, ML workers, and database occurs at internal data center speeds.

Speaker Notes: Highlight the contrast between having an always-on expensive server vs. serverless Cloud Run that only charges when an analysis is actually occurring.
